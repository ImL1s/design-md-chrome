# AGENTS.md — TypeUI `design-md` for AI coding tools

This file tells **every AI coding tool that reads `AGENTS.md`** (Codex CLI, Cursor, Windsurf, Zed, Warp, Aider, Gemini CLI, Copilot Coding Agent, Junie, Goose, opencode, and ~60+ others via the Linux Foundation AAIF / agents.md spec) **how to extract design tokens from a live webpage** using the bundled CLI.

Claude Code / Cline / custom skills that need their own slash command wrapper invoke the **same CLI** via a thin per-tool file in `.ruler/extract-design.md` → generated by `npx ruler apply`. No tool has its own extraction logic; the CLI is the single source of truth.

---

## What this project does

`design-md` (this repo) extracts design tokens — typography, colors, spacing, radius, shadows, motion — from any rendered webpage and writes either:

- `DESIGN.md` — human/AI-readable design-system documentation
- `SKILL.md` — agent-ready skill file with YAML frontmatter + TypeUI managed-block markers

File format reference: <https://www.typeui.sh/design-md>.

## How AI agents should use this repo

### 1. Install dependencies once per machine

```bash
npm install
```

Pulls `puppeteer-core` + `chrome-launcher` (no ~170 MB Chromium download — your host Chrome is used).

### 2. Run the CLI

```bash
# Extract design tokens from any URL into DESIGN.md
node bin/design-md.mjs extract https://www.typeui.sh -o DESIGN.md

# Extract as an agent-ready SKILL.md (with managed-block markers)
node bin/design-md.mjs extract https://stripe.com --mode skill -o stripe.skill.md

# Print extraction diagnostics to stderr while writing design doc
node bin/design-md.mjs extract https://github.com --mode design -o gh.md --verbose

# v0.6+: emit CSS variables (:root { --color-1: ...; }) instead of markdown
node bin/design-md.mjs extract <url> --format css-vars -o tokens.css

# v0.6+: raw normalized payload (schema-stamped) for machine pipelines / regression tests
node bin/design-md.mjs extract <url> --format json -o payload.json

# v0.6+: batch extraction — N URLs → one file per URL in a directory
node bin/design-md.mjs extract https://a.com https://b.com https://c.com -o out-dir/

# v0.6+: batch via --input file (one URL per line, # comments ignored)
node bin/design-md.mjs extract --input urls.txt -o out-dir/ --format css-vars

# v0.6+: wait for a selector to appear (SPAs with late-loading design systems)
node bin/design-md.mjs extract https://slow-app.com --wait-selector ".app-ready" -o DESIGN.md

# v0.6+: unconditional additional delay after page is interactive
node bin/design-md.mjs extract <url> --wait 2000 -o DESIGN.md

# DEPRECATED: --dump-payload still works but emits a deprecation warning.
# Prefer --format json.
node bin/design-md.mjs extract <url> --dump-payload -o payload.json
```

Exit codes: `0` all URLs ok, `1` at least one URL failed (batch mode reports `[N/M] FAILED: ...` to stderr and keeps going), `2` usage error.

### 3. Use the produced file

- **Cursor / Windsurf / Cline / Claude Code**: drop the SKILL.md into your project's skill directory (`.cursor/commands/`, `.windsurf/workflows/`, `.clinerules/`, `.claude/skills/*/SKILL.md`)
- **Codex CLI / Gemini CLI / Aider / Warp**: cite `DESIGN.md` alongside this `AGENTS.md` — the rules are inline
- **Generic MCP-style or other agents**: invoke the CLI via shell; read the resulting markdown back via standard filesystem tools

## What you must NOT do

- Do **not** re-implement token extraction inside a tool's skill file. The extraction lives in `content-script.js` (the Chrome extension payload) — the CLI injects it via CDP into an isolated world. Re-implementing the sampling logic will drift from the extension.
- Do **not** hand-edit `content-script.js` under the assumption it is regenerated. The α path (v0.5) uses it unchanged. The β path (if activated — see `docs/spike-results.md`) would regenerate `content-script.js` from `src/extract-core.js` + `scripts/content-script.template.js` via `scripts/build-content-script.mjs`; the 4-step CI guard (git diff + grep sentinel + `node --check`) blocks hand-edits in that mode.
- Do **not** bump `manifest.json` version ad-hoc. Use the `/release` skill (or the commit convention — see `CLAUDE.md`). The manifest version is the release signal for the Chrome extension AND the CLI package version.

## Verification contract

Any change touching `lib/*.mjs`, `content-script.js`, `scripts/*.mjs`, `bin/*.mjs`, or `tests/*.mjs` must keep these green:

```bash
node tests/run-tests.mjs                   # unit tests
node tests/run-integration-tests.mjs       # end-to-end CLI + structural contract against baseline
```

The second command launches a real headless Chrome multiple times; budget is about one minute on a warm host.

Intentional payload-shape changes must regenerate `tests/fixtures/sample-dashboard.baseline.json` via `npm run capture:baseline` and document the reason in `docs/baseline-capture.md` in the same commit.

## Files that define the contract

- `content-script.js` — the extraction payload (pure browser DOM, no ES module imports)
- `lib/normalize.mjs`, `lib/generate-design-md.mjs`, `lib/generate-skill-md.mjs`, `lib/validate.mjs` — token normalization + markdown generation
- `lib/schema.mjs` — `__schemaVersion` + `writeWithSchema()` used by CLI and future storage writes
- `tests/check-contract.mjs` — structural-contract oracle (hex exact, px ±1, font-family canonicalized string-eq, others ±2%, SHA-256 content-hash of top-N colors/fonts)
- `tests/fixtures/sample-dashboard.html` — deterministic fixture
- `tests/fixtures/sample-dashboard.baseline.json` — committed oracle
- `docs/spike-results.md` — Day-0 CDP-inject spike outcome (α vs β decision)
- `docs/baseline-capture.md` — how to regenerate the baseline
- `.ruler/` — single-source instructions that `npx ruler apply` fans out to `.claude/`, `.cursor/`, `.windsurf/`, `.clinerules/`
